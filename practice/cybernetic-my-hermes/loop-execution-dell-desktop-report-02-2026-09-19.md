## 6. 第五步：根因分析

### 案例 1：前馈输出缺失（09-19 EventPilot）

| 层级 | 分析 |
|------|------|
| 现象 | 用户发 folder + "回到这个项目上来，继续进行开发"，agent 直接进入状态读取，无前馈/避坑清单 |
| 直接原因 | "继续开发/状态读取"型任务开场未走前馈 |
| 深层原因 | feedforward_startup 技能要求"新任务开始前自动执行"，但**未明确覆盖"续做型"任务**——agent 视其为"已在进行的工作流"而非"新任务"，故跳过前馈 |
| **根因判定** | **规律错（L1 触发边界定义不全）**，非执行能力问题——技能有要求，但对任务类型的分类覆盖不全（只有"短篇创作/代码输出/架构设计/问题排查/日常问答/其他"，无"续做型"条目） |
| 修复 | 提议将"续做型"（用户发 folder + 继续指令）也视为新任务、强制前馈；下沉至 L1/技能分类 |

### 案例 2（正向）：闸门迁移有效

08-29 迁移的三重防护在 09-19 实战中首批真实应用即正确执行（push 前后 P0.5、作者一致、敏感扫描）。说明迁移无适配残留，"跨部署一致性"机制在本期得到验证。

### 分析结论
本周期仅一个真实任务，无新 L3 缺陷；核心问题落在 L1 前馈触发边界。闸门防护架构经受住真实 push 检验。

## 7. 第六步：可复用提炼

1. **"续做型任务也需前馈"**：用户发已分析过的项目 + "继续开发"时，前馈仍是第一动作（读状态 ≠ 前馈，前馈是主动输出避坑/风险清单）。这是本轮最具复用价值的教训。
